Build plan

Oscar's Music

A public songbook and booking site for Oscar Nash. It is designed to be cheap to run and simple for Oscar and a couple of other admins to look after without a developer on call. Estimated effort: five weeks part-time to a launch-ready first version.

Decisions so far

Public siteStreaming only, no downloadsNo co-writer approval stepPlaylists are called Collections

Streaming only means audio plays in the page and scores are shown for viewing. Browsers can still be used to save files if someone is determined, so this deters casual copying and does not prevent it.

What the site includes

For visitors

  • Songs and Collections, A to Z, with search by title or co-writer
  • Song page with audio player and Lyrics, Chords and Score tabs
  • Optional links to YouTube, Spotify, Apple Music and others, on both songs and Collections
  • Calendar of live sessions with booking or info links
  • About page and a Contact page

For admins

  • Sign in by email link
  • Add and edit songs, with optional image, audio, lyrics, chords, score and streaming links
  • Put any song in any number of Collections and set the order in each
  • Add and remove calendar sessions
  • Add YouTube, Spotify or other recording links to a Collection, for example a whole live session
  • Edit the About page text and photo without a developer

Contact page

  • Book Oscar (also a button in the header)
  • Offer to play or record together
  • Donate
  • Send a message

Recommended stack

LayerChoiceWhy
Front endNext.js (React) on VercelFast public pages that search engines can read, so song titles are findable. Free tier is enough to start.
DatabaseSupabase PostgresSongs, people and ordered Collections suit a relational database. Built-in text search.
Admin sign-inSupabase Auth, email magic linkNo passwords. Only addresses on the admin list can edit.
FilesSupabase StorageAudio, images and scores. Move audio to Cloudflare R2 if storage grows past a few GB.
Email from Contact formResendDelivers enquiries to Oscar's inbox. Bot protection with Cloudflare Turnstile.
DonationsStripe Payment Link or PayPalThe Donate button opens the provider's own payment page, so the site never touches card details.
Running costAbout £0–20 a monthFree tiers at first, plus a domain name. The Supabase paid plan if audio passes 1 GB.

Data model

TableKey fields
songsid, title, sort_title, note, key, image_url, audio_url, lyrics, chords, score_url
song_linkssong_id, service, url (YouTube, Spotify, Apple Music, other). Zero or more per song.
peopleid, name. One row per co-writer, so spellings stay consistent.
song_creditssong_id, person_id, role, where role is lyrics or music
collectionsid, title, sort_title, note, image_url
collection_songscollection_id, song_id, position. A song can appear in many Collections, and each Collection has its own order.
collection_linkscollection_id, service, url. Recordings of a whole session or album, zero or more per Collection.
about_pageA single row: heading, tagline, body, image_url. Admins edit it from the site itself.
sessionsid, title, starts_at, venue, city, kind, note, link_url for the Calendar
enquiriesid, reason, name, email, details, created_at. Kept so nothing is lost if an email fails.
adminsemail

sort_title drops a leading “The” or “A”, so “The Bell Tower Waltz” files under B. Search uses a Postgres index over titles and credited names. Past calendar sessions are hidden from visitors but kept.

Timeline

Week 1
Foundations. Project setup, database, admin sign-in, deployment. Songs list with A to Z and search working on sample data.
Week 2
Song page. Audio player, three tabs, score viewer, streaming links, square image handling, phone layout.
Week 3
Admin tools. Add and edit songs, file uploads with progress, co-writer autocomplete, Collections with ordering and notes.
Week 4
Calendar and Contact. Sessions with booking links, the Book Oscar button, the four-way contact form with email delivery and spam protection, donation link, About page.
Week 5
Polish and launch. Import Oscar's existing songs, accessibility check, custom domain, backups, a one-page admin guide.

Getting it online

The mockup is a prototype that shows how the site looks and works. It does not save anything, so the real site has to be built and hosted before Oscar can fill it in. The route below gets him entering songs about halfway through the build, in the same database that goes live, so nothing is re-typed.

StepWhat happensWho
1. AccountsCreate GitHub, Vercel, Supabase and Resend accounts under an email address Oscar and Tim both control, and buy the domain name. Oscar's organisation owns everything, so nothing depends on one person.Tim and Oscar, about an hour
2. Private previewDeploy the first working version to a temporary web address in week 1. It is hidden from search engines and shows a “coming soon” note to visitors until launch.Build
3. Oscar starts entering songsWhen the admin tools are ready (end of week 3), Oscar and the other admins sign in and add songs, Collections, calendar dates and the About text. Feedback goes straight into the next week's work.Oscar and admins
4. LaunchConnect the domain, remove the “coming soon” note, test the Contact form and donation link end to end, and share the address.Build, then Oscar announces
5. After launchAdmins run the site day to day. A one-page guide covers adding songs, Collections, sessions and the About page.Admins

Alternative. A website builder such as Squarespace or WordPress would be online in days, but searching by co-writer, ordering songs inside Collections and the three-tab song page would each need workarounds or paid plugins. A custom build costs more up front and fits what Oscar described.

Open questions

  • Donations. Which provider does Oscar already have an account with? Does he want a recurring option as well as one-off gifts?
  • Score format. A PDF per song is simplest. Showing scores generated from MusicXML is possible later.
  • Audio size. Compress to MP3 on upload so playback is quick on phones.
  • Contact inbox. Which email address should enquiries go to, and should booking enquiries also go to a second person?
  • About page. Oscar's text and a photo. The mockup uses placeholders, and admins can replace both once the site is live.
  • Domain name. For example oscarsmusic.com or oscarnash.com. Worth checking what is free.
  • Later ideas. Printable set lists, shareable Collection links, a mailing list sign-up.
